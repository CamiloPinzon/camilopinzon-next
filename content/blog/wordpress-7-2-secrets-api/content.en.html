What happened

On November 17, 2026, the WordPress team announced that the Secrets API will no longer ship with WordPress 7.2. The news came as an update to the developer note that introduced it, and the hosting team repeated it in its own note: the code was reverted from 7.2. Version 7.2 is still due on December 8, without this feature.

We published this article on November 16, while the Secrets API was still in 7.2 and there was an open request to pull it. We've updated it to cover the decision and what it means for your site.

What the Secrets API was

Lots of plugins need a key to talk to another service: your payment gateway, your email provider, your CRM. Today those keys usually sit in the database as plain text, like a password written on a sticky note in a desk drawer.

The Secrets API was going to be a safe for those keys. It stored them encrypted, and opening them took a key that lived in a different file, wp-config.php, called WP_SECRETS_KEY. Existing sites had to add that key by hand, and if it was lost or changed, the stored keys could no longer be read. That was at the heart of the debate: in the comments on the note, someone asked to pull it from 7.2, and its author wanted to see a working integration with a real hosting provider first.

How it affects you

For most sites, nothing. WordPress didn't use the safe for anything of its own, so updating to 7.2 works the same as before. You no longer need to add WP_SECRETS_KEY, and Site Health won't ask you for it.

If your site ran the 7.2 betas. According to the hosting team, removing the code doesn't remove the data. On those sites, any stored keys stay behind, along with a new administrator permission (manage_secrets) and the WP_SECRETS_KEY constant in wp-config.php. If you update from the WordPress dashboard, the Secrets API files also stay on the server. If you update with WP-CLI, the command-line tool, they get removed.

If a plugin was already using it in testing, it won't find it in 7.2.

What comes next. There's no official date for it to return. Before the decision, the note's author wrote about wanting to target at least 7.3, but that isn't an announcement.

What you can do

  1. If your site never ran a beta, nothing. Update to 7.2 when it's out, as usual: back up first and do a quick check afterward.
  2. If you already added WP_SECRETS_KEY, don't delete it casually. It does no harm. If you do remove it, keep a copy: any keys stored during testing can only be read with it.
  3. If you have a staging copy that ran the betas, ask your developer to review the leftovers the hosting team's note describes and decide whether to clean them up.
  4. If a plugin asked you to set up the Secrets API, ask its author what they plan to do now that it isn't in 7.2.
